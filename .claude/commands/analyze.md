# /analyze

全量重跑真题分析。产物整体覆盖 `分析/`。

规则以仓库根 `CLAUDE.md` 为准，本文件只定义流程。

---

## 步骤

### 1. 预检

- 列出 `papers/` 下所有题面文件与题目总数（按 `CLAUDE.md` §2.1 的三种卷内结构分别计数）
- 检查题号连续性、重复题号、重复年份文件、乱码与格式异常
- 写入 `分析/预检报告.md`
- 异常先报告，**不自行修补**，等用户确认后再继续

### 2. 解析

逐题提取：年份、题号、分值、题干全文。
不做任何判断，只提取。剔除 `【答案】`/`【解析】` 段落（见 `CLAUDE.md` §2.4）。

输出：本轮解析到 N 题，覆盖年份 X–Y。

### 3. 考点标注

按 `CLAUDE.md` §3 的粒度逐题标考点。

- 主考点 + 次考点
- 无法判定的标 `?`，进 `待确认.md`

**标注完成后暂停**，输出考点标签全集（去重后的列表）给用户过目。用户确认粒度合适再继续——粒度不对在这一步返工代价最小。

### 4. 题型分类

按 `CLAUDE.md` §5 固定取值分类。取值外的情况进 `待确认.md`。

### 5. 同题识别

两两比对解题路径。确定的归组，不确定的进「疑似」。
识别范围限于同一科目内（本仓库只有 `数学一`）。

### 6. 统计与写入

生成 `CLAUDE.md` §4.1–4.5 五个文件，整体覆盖。

### 7. 解法推断

逐题写解题路径，全部标 `status: 待核对`。

已存在的 `解法.md` 中标为 `已核对` 的节：**保留原内容，不覆盖**。这是本流程唯一的例外——用户核对过的内容是人工输入，重跑不得抹掉。

### 8. 报告

- 本轮题数、考点数、同题组数
- 新增考点标签（与上轮 diff）
- `待确认.md` 条目数
- `解法.md` 中待核对 / 已核对的数量

### 9. Git

新分支提交，不直接推 main。

---

## 禁止

- 步骤 1 之后不等确认直接跑完
- 步骤 3 之后不暂停直接跑完
- 覆盖 `已核对` 的解法
- 在 `待确认` 里塞「我觉得可能是」——不确定就是不确定，不给倾向性猜测
