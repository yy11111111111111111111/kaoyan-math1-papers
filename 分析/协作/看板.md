# 协作看板

**跨机器、跨模型、跨对话的唯一总线。**

Claude Code 的 `ListAgents` / `SendMessage` 只能在**同一台机器**上互通。
远程会话（云端容器）与本机会话之间没有直连，所以协调必须走这份文件。

## 怎么用

**每个 agent 开工前先读这里，收工后更新自己那一行。**

- 一个 agent 只改**自己那一行**，不要改别人的。
- **分支名以你实际所在的分支为准**（`git rev-parse --abbrev-ref HEAD`）。
  云端会话的分支由 harness 分配，与派工时预写的名字不同**不算 inconsistency**，
  直接把实际名字写回你那一行即可。
- 已交付合入的行**保留不删**——它记录了「这块是谁在哪个分支上做的」，
  出问题时要靠它回溯。
- 改完连同你的产出一起 commit。改看板不单独开 commit。
- 冲突了就以后 push 的为准，把被覆盖的那行原样补回去——这份文件不值得为它解冲突。
- **它不是聊天记录。**只写「现在是什么状态」，不写过程。要留讨论痕迹就写进
  `分析/审查/` 下的报告文件。

## 需要对方回应时

写进自己那一行的 `waiting_for`，**并说清楚在哪个文件的哪一节**：

```yaml
waiting_for: "claude-code-remote 判定 A6p 的拆分是否过度切分（见
  分析/审查/DeepSeek-audit-batch1-<head>.md §findings.blockers 第 2 条）"
```

不要写「等 Claude 回复」——没人知道你在等什么。

## 发现 blocker 时

不要只写在看板上。按 `METHOD_FAMILY_HANDOFF.md` 的四类定义
（B1 漏解 / B2 direct counter-witness / B3 schema 表达力 / B4 语义级状态错误）
写进审查报告，看板这里只放一行指针。

看板会被人扫一眼，报告才会被认真读。
