# 检验脚本

## 为什么有这个目录

`命题模型.md` 原来写着「检验代码为一次性脚本，未入库」。这正是 `p=0.81` 这个
**复现不稳的数字能在 10 份文件里传播一年**的结构原因——没有人能重跑它。

规则：**凡是会支持长期主张的统计检验，代码必须落在这里，并输出完整的元数据记录。**
只有这样，审阅方的职责才是「审 estimand / null / 推论强度」，而不是审一串无法复现的数字。

## 怎么跑

```bash
cd 分析/tests
python3 test_E.py      # 检验 E：频次 → 跨题型分散度（已否证）
python3 test_D1.py     # 检验 D1：功能类型 × 高数解答位
python3 test_D2.py     # 检验 D2：具体考点 × 高数解答位
python3 test_G.py      # 检验 G：空窗 → 下一场出现
```

无第三方依赖，标准库即可。每个脚本把结果打成一段 YAML，字段固定：

```yaml
test_id:              # 检验编号
input_sha:            # 考点标注.tsv 的 sha256 前 16 位，用于确认输入未变
inclusion_rule:       # 纳入了哪些行，排除了什么，为什么
estimand:             # 到底在估计什么量（不是「统计量是什么」）
statistic:            # 统计量的定义
null_model:           # 零模型如何构造，保留了哪些结构
randomization_unit:   # 随机化的单位
iterations:           # 置换/自助次数
seed:                 # 随机种子
observed:             # 观测值
null_summary:         # 零模型分布的摘要
p_value:              # p 值，注明单侧/双侧
interpretation:       # 能说什么、不能说什么
known_contamination:  # 已知的污染与局限，必须写
generated_at:
```

`known_contamination` 不是可选项。检验 D1 的因变量来自未核验的 `解法.md`、
检验 G 的 2022 缺失处理——这类问题写在结果旁边，比写在别处更难被忽略。
