# 方法族 · 高数第一批（v3.5.0）

## 0. schema v1.3.1 与审核 lineage

### 0.1 v1.3：输出对象、后续组合与 terminal 性质分离

```yaml
produces: transformed_problem | candidate_set | subproblems | result_object
followup_actions:
  mode: all_of | any_of | optional_any_of | sequence
  actions: [...]
terminal_when:
  - 当前 action 的直接输出在什么 task/context 下已经满足 response requirement
```

三个字段互不代替：

```text
transformed_problem 得到一个等价的、或足以继续求解的新问题/新表示
candidate_set      得到候选对象集合，还必须分类、比较或筛选
subproblems        原问题被拆成多个仍需分别完成的子问题
result_object      得到数值、函数、点集、界或定性结论等数学结果对象

followup_actions   先按 followup item 的 when（若有）与所引 action 的 applies_when 过滤，再由 mode 解释剩余项的逻辑关系
terminal_when      只判断当前输出在声明 task/context 下是否已经满足整题 response requirement
```

`result_object` **不等于**「整题已完成」。例如 A1 无约束 Hessian 路线可以直接产生一组已分类的内部候选，但被闭区域 framework 调用时仍不是全局最值答案。反过来，`transformed_problem` 也可能在设问只要求渐近表示时成为 terminal。terminal 性质只能由 `terminal_when` 按 task/context 判定，不能永久编码进 action 类型。

`followup_actions.mode` 的语义：

```text
all_of          当前上下文适用的动作都要完成，次序未声明
any_of          当前上下文适用的动作至少选择一个完成
optional_any_of 可以不继续；若继续，则从适用动作中选择至少一个
sequence        按 actions 的记录顺序完成当前上下文适用的动作
```

若这四档无法表达新的真实关系，必须登记 `pending_schema_declaration`，不得临场扩枚举。`actions` 可以直接引用 family action ID，也可以写成当前 framework 内定义明确的后续数学操作；需声明目标或条件时写成 `{ action, target?, when? }`。执行器先核对 item 的 `when`（若有）和所引 action 自身的 `applies_when`，过滤后再应用 `mode`。

`subroute_of` 继续只表示：额外条件收窄后，父路线的同一机制得到特殊实现，执行子路线时不存在一个独立的「调用父路线」步骤。跨 action 的实际调用一律写入 `followup_actions`，旧字段 `invokes` 与 `requires_followup` 自 v1.3 起废弃。

### 0.1.1 v1.3.1：关闭三个控制流缺口

v1.3 把输出、后续与 terminal 分成了三个字段，但**没有规定它们之间的执行关系**。GPT 对 v3.2 的 full-file audit 指出三处歧义，本节逐条关闭。**这是 patch 不是重做，`produces` 四值与 `mode` 四档均不变。**

**S1 · 执行顺序固定**

```text
1. execute current action
2. obtain direct output            ← produces 描述的就是这一步的对象
3. evaluate terminal_when
4. if terminal == true:   stop current route
5. if terminal == false:  evaluate followup_actions
```

`terminal_when` **先于** `followup_actions` 求值。v1.3 未声明先后，导致「terminal 为真时是否仍要跑 followup」「followup 跑完是否回头再判 terminal」两处都可以自圆其说。现在只有一条合法读法。

**S2 · `optional_any_of` 不得假完成**

```yaml
followup_actions:
  mode: optional_any_of
  actions: [...]
  on_skip: return_to_parent_router      # v1.3.1 起，optional_any_of 必填
```

若 `terminal_when` 求值为 **false** 而执行器选择不继续，**不等于 response requirement 已满足**。`on_skip: return_to_parent_router` 的语义是：当前 action 不再继续，控制权交回父 router 重新选路线。

⚠️ **`optional_any_of` + `terminal_when == false` + 零 follow-up + 无 `on_skip` = 任务未完成而被当作完成。**这是 v1.3 唯一能"静默漏解"的组合，v1.3.1 用必填的 `on_skip` 堵掉。

**S3 · `action_ref` 与 `local_operation` 分型**

v1.3 的 `actions: [...]` 里混住了两类对象：一类是 family action 的引用（`A2`、`A3G`），一类是局部数学操作（「计算所得积分」「在约束内逐点分类」「比较全部候选」）。前者要走被调用 action 自己的 `applies_when`，后者没有 `applies_when` 可走。混用同一个无类型字段，等于让执行器无法知道该不该做 applicability 检查。

```yaml
actions:
  - kind: action_ref
    action: A2
    target: ...        # 可选
    when: ...          # 可选
  - kind: local_operation
    operation: ...
    when: ...          # 可选
```

- **`action_ref`** —— 执行前必须同时检查：① follow-up item 自身的 `when`；② `target`（若有）；③ **被调用 action 的 `applies_when`**。三者任一不满足则该项被过滤掉，再由 `mode` 解释剩余项。
- **`local_operation`** —— 只检查自身 `when`。**不得伪装成 family action**，也不进入 route-scan 的候选计数。

未标 `kind` 的裸字符串在 v1.3.1 中视为**待迁移**，lint 会报出；不自动推断类型。

  mechanism:
    statement: |
      补面（曲面·第二类）：设 S ∪ Σ₀ = ∂V 且方向统一取外侧，由 Gauss 公式
        ∬_S F·n dS + ∬_{Σ₀} F·n dS = ∭_V (∇·F) dV
      故
        ∬_S F·n dS = ∭_V (∇·F) dV − ∬_{Σ₀} F·n dS。
      补线（平面·曲线·第二类）把 Gauss 换成 Green、体域换成平面区域，结构相同。
      Stokes 的结构不同：∮_L F·dr = ∬_S (∇×F)·n dS，**S 在 admissible spanning surfaces 中选择**，
      因此它不是「把不封闭补成封闭」，而是「把线积分换到任一张方便的曲面上」。
    why_action_follows: |
      补域的全部作用是去掉「不封闭」这一个障碍，代价是多算一块 Σ₀，
      **合法性条件（v3.3 更正）**：v3.2 写「合法性只要求闭合与定向一致」，
      这被本 family 自己的 B1 反例推翻——B1 里的场闭合、定向也一致，
      公式仍不适用，因为区域内含奇点。补域路线的合法性至少要求：
        ① 原载体与补的部分合起来构成**完整的闭边界**，无缝隙无重叠；
        ② 载体与补面/补线本身满足所用定理要求的**正则性**（分片光滑、可定向）；
        ③ 向量场在定理所需的**整个**区域上满足光滑性条件（分量有连续偏导）；
        ④ 该区域内**无未处理的奇点**；
        ⑤ 各边界分量按同一剩余区域的**诱导正向**取向。
      在这五条都满足的前提下，选哪块补面才是效率问题（标准是「Σ₀ 上好算」）。
      Stokes 的自由度在选 S，不在补 S——把两者混为一谈正是 v1 的结构错误。
