# 方法族 · 高数第一批（v2）

## 0. schema v1.2 与本轮改动

### v1.2 新增两个字段（不升 v2，兼容扩展）

```yaml
produces: final_result | candidate_set | transformed_problem | subproblems
requires_followup: [...]
```

**`produces` 的判定口径（v1.2 锁死）**：当前 action 按其声明粒度**执行一次后，直接得到的数学对象类型**。它与「有没有 followup」高度相关，但**不由 followup 定义，更不由「通常是不是一步做完」定义**。

```text
final_result       已进入题目的 response space；后面只剩核验与书写
transformed_problem 得到一个等价的、或足以继续求解的新问题/新表示
candidate_set      得到候选对象集合，还必须分类、比较或筛选
subproblems        原问题被拆成多个仍需分别完成的子问题
```

⚠️ 即使某道题「替换之后肉眼立刻看出答案」，也不把 A1 改成 `final_result`——否则同一个 action 的类型会随题目难易漂移。洛必达执行一次的结构是 `lim f/g → lim f′/g′`，**它直接产出的就是另一个极限问题**；新极限恰好等于 1 只说明 followup 很便宜，不改变 output type。

**`subroute_of` 与 `invokes` 的判据（v1.2 锁死）**：

```text
subroute_of  额外条件收窄后，父路线的同一数学机制得到一个特殊实现；
             执行子路线时，不存在一个独立的「调用父路线」步骤。
invokes      当前动作先产生新对象/新子任务，之后还必须显式执行另一个 action。
```

例：A1p（投影公式）本质就是参数化 r(x,y) = (x, y, z(x,y)) 之后
`dS = ‖r_x × r_y‖ dxdy` 的标准特例，执行它时并没有「再调用一次 A1」这个步骤，
因此是 `subroute_of: A1`。而 A8（合一投影 → 再积分）、A5（先平方 |∇f| → 再 Lagrange）
都是先产生新对象再显式执行另一动作，因此是 `invokes`。

据此，**A5（|∇f|² 的 Lagrange）与 A8（合一投影）的 `subroute_of` 已删除**，改为
`produces: transformed_problem` + `invokes`。它们是「先变换再调用」，不是同层变体。

### 第三轮验收裁定的处置（v3.1）

### 第二轮验收意见的逐条处置

  name: 一元极限的方法选择
  status: candidate

  scope:

## 2. `calc.vector-integral.route-selection`（v2：重写为两级 router）

第一轮判定「填法错了要重写」，理由是把四类积分与三个定理混进同一个 router。确认成立：`F1 = 是否封闭 → A3` 作为统一路由从根上不成立——Stokes 的曲面**本身不需要封闭**，第一类积分也不因载体封闭就能套第二类公式。
